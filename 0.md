## 💡 1️⃣ IDE – Twoje główne narzędzie pracy / IDE – Your Main Working Tool

An IDE (Integrated Development Environment) is like **MS Word or OpenOffice for programmers** – a place where you write, run, and test code.

IDE ([Integrated Development Environment](https://en.wikipedia.org/wiki/Integrated_development_environment)) to coś jak **MS Word lub OpenOffice dla programistów** – miejsce, w którym piszesz, uruchamiasz i testujesz kod.

An IDE can:

IDE potrafi:

- highlight syntax / kolorować składnię
- suggest code completions ([*IntelliSense*](https://en.wikipedia.org/wiki/Intelligent_code_completion)) / podpowiadać kod (tzw. *IntelliSense*)
- help you debug step-by-step / pomagać w [debugowaniu](https://en.wikipedia.org/wiki/Debugger) (śledzeniu krok po kroku)
- integrate with Git and testing tools / integrować się z Gitem i testami

🧠 **Dlaczego to ważne / Why it matters:**

A good IDE helps you write code faster, catch errors early (similar to how Word highlights spelling or grammar errors), and provides useful programming tools with extensibility through plugins.

Dobre IDE pozwala szybciej pisać kod, wychwytuje błędy wcześnie (podobnie jak Word podkreśla błędy ortograficzne czy gramatyczne), dostarcza narzędzi przydatnych przy programowaniu i pozwala na rozszerzalność przez pluginy.

## 💡 2️⃣ Python & pyenv – wersje języka / Python & pyenv – Language Versions

[Python](https://en.wikipedia.org/wiki/History_of_Python) comes in multiple versions (e.g. 3.9, 3.11, 3.14).

[Python](https://en.wikipedia.org/wiki/History_of_Python) to język, który występuje w różnych wersjach (np. 3.9, 3.11, 3.14).

[`pyenv`](https://github.com/pyenv/pyenv) lets you install and switch between them without conflicts — similar to how you can have multiple versions of Office (2016, 2019, 2021) on one computer.

[`pyenv`](https://github.com/pyenv/pyenv) pozwala zainstalować kilka wersji i przełączać się między nimi bez konfliktów — podobnie jak możesz mieć kilka wersji Office'a (2016, 2019, 2021) na jednym komputerze.

Niektóre projekty wymagają starszych lub nowszych wersji Pythona. `pyenv` zapewnia, że każdy projekt używa dokładnie tej, której potrzebuje.

## 💡 3️⃣ `uv` – menedżer środowisk i paczek / `uv` – Environment & Package Manager

`uv` is a **modern, ultra-fast environment and package manager**.

`uv` to **nowoczesny, bardzo szybki menedżer środowisk i bibliotek**.

It combines the functions of older tools (`pip`, `venv`, `poetry`) into one command — like a **smart project manager** that not only installs tools but also creates a dedicated workspace and tracks what you need.

Łączy funkcje starszych narzędzi (`pip`, `venv`, `poetry`) w jednym poleceniu — jak **mądry kierownik projektu**, który nie tylko instaluje narzędzia, ale też tworzy dedykowane miejsce pracy i śledzi czego potrzebujesz.

With `uv`, you don't have to manually create `.venv` directories — it handles everything automatically.

Dzięki `uv` nie musisz ręcznie tworzyć katalogów `.venv` — wszystko robi automatycznie.

📘 **Documentation / Dokumentacja:**

[uv Getting Started (Astral)](https://docs.astral.sh/uv/getting-started/installation/)

*Read sections: "Installation" and "Creating a project" / Przeczytaj sekcje: "Installation" i "Creating a project"*

🧠 **Dlaczego to ważne / Why it matters:**

Each project may need different library versions. `uv` creates isolated environments so dependencies never clash.

Każdy projekt może wymagać innych wersji bibliotek. `uv` tworzy oddzielne środowisko dla każdego projektu, dzięki czemu nie ma konfliktów.

### 📚 Co to są biblioteki i paczki? / What Are Libraries and Packages?

A [library](https://en.wikipedia.org/wiki/Library_(computing)) (or package) is **a collection of pre-written code** that saves you time — like an app store for programmers.

[Biblioteka](https://pl.wikipedia.org/wiki/Biblioteka_programistyczna) (ang. library lub package) to **zbiór gotowego kodu**, który oszczędza Ci czas — jak sklep z aplikacjami dla programistów.

For example, `requests` simplifies web downloads, and `pandas` helps analyze data.

Np. `requests` ułatwia pobieranie danych z Internetu, a `pandas` pomaga analizować dane.

Adding libraries extends your program's functionality without writing everything from scratch.

Dodając biblioteki, rozszerzasz możliwości swojego programu bez pisania wszystkiego od zera.

---

### 🔍 Gdzie znajdować pakiety? / Where to Find Packages?

**[PyPI (Python Package Index)](https://pypi.org)** is the official repository for Python packages — like Google Play or App Store, but for Python libraries.

**[PyPI (Python Package Index)](https://pypi.org)** to oficjalne repozytorium pakietów Pythona — jak Google Play lub App Store, ale dla bibliotek Pythona.

**How to search for packages / Jak wyszukiwać pakiety:**

1. **Search on PyPI website**: Go to [pypi.org](https://pypi.org) and use the search bar.

   **Szukaj na stronie PyPI**: Przejdź na [pypi.org](https://pypi.org) i użyj paska wyszukiwania.

2. **Check package details**: Click on a package to see its description, version history, and documentation.

   **Sprawdź szczegóły pakietu**: Kliknij na pakiet, aby zobaczyć jego opis, historię wersji i dokumentację.

3. **Verify package quality**: Look for indicators like download count, last update date, and GitHub stars.

   **Zweryfikuj jakość pakietu**: Sprawdź wskaźniki jak liczba pobrań, data ostatniej aktualizacji i liczba gwiazdek na GitHubie.

**How to check package versions / Jak sprawdzać wersje pakietów:**

```bash
# Check installed package version / Sprawdź zainstalowaną wersję pakietu
uv pip show requests

# List all installed packages / Wyświetl wszystkie zainstalowane pakiety
uv pip list

# Check for outdated packages / Sprawdź przestarzałe pakiety
uv pip list --outdated
```

**Example: Finding a package for working with dates**

**Przykład: Wyszukiwanie pakietu do pracy z datami**

1. Search "python date manipulation" on PyPI → Find `arrow` or `python-dateutil`

   Wyszukaj "python date manipulation" na PyPI → Znajdziesz `arrow` lub `python-dateutil`

2. Compare packages by checking their PyPI pages for popularity and recent updates

   Porównaj pakiety sprawdzając ich strony PyPI pod kątem popularności i świeżości aktualizacji

3. Install with: `uv add arrow`

   Zainstaluj przez: `uv add arrow`

### ⚙️ `uv` vs `pip` – Różnice / Differences

| Narzędzie / Tool | Co robi / What it does | Różnica / Difference |
|------------------|------------------------|----------------------|
| `pip install requests` | Instaluje bibliotekę / Installs library | Tylko instalacja — musisz ręcznie zaktualizować `requirements.txt` / Just installs — you must manually update `requirements.txt` |
| `uv add requests` | Instaluje **i** aktualizuje `pyproject.toml` / Installs **and** updates `pyproject.toml` | Automatyczna dokumentacja zależności / Automatic dependency tracking |

⚠️ **Note / Uwaga:**

Older tutorials use `pip install ...`. Modern projects use `uv add ...`.

Starsze tutoriale używają `pip install ...`. Nowoczesne projekty używają `uv add ...`.

### 📝 `.gitignore` – ignorowanie niepotrzebnych plików / Ignoring Unnecessary Files

**[`.gitignore`](https://git-scm.com/docs/gitignore)** is a special file that tells Git which files or folders to ignore — like telling a camera which things not to photograph.

**[`.gitignore`](https://git-scm.com/docs/gitignore)** to specjalny plik, który mówi Gitowi, które pliki lub foldery ignorować — jak mówienie aparatowi, czego nie fotografować.

**Why you need it / Dlaczego tego potrzebujesz:**

You should NOT commit certain files to Git:

Nie powinieneś commitować pewnych plików do Gita:

- **Virtual environments** (`.venv/`, `venv/`) — they're large and project-specific

  **Środowiska wirtualne** (`.venv/`, `venv/`) — są duże i specyficzne dla projektu

- **Python cache** (`__pycache__/`, `*.pyc`) — automatically generated files

  **Cache Pythona** (`__pycache__/`, `*.pyc`) — automatycznie generowane pliki

- **Secret files** (`.env`, `credentials.json`) — contain passwords and API keys!

  **Pliki z sekretami** (`.env`, `credentials.json`) — zawierają hasła i klucze API!

- **IDE settings** (`.idea/`, `.vscode/`) — personal configuration

  **Ustawienia IDE** (`.idea/`, `.vscode/`) — osobista konfiguracja

- **OS files** (`.DS_Store`, `Thumbs.db`) — system-specific junk

  **Pliki systemowe** (`.DS_Store`, `Thumbs.db`) — śmieci specyficzne dla systemu

---

### 🎯 How to create `.gitignore` / Jak stworzyć `.gitignore`

**Method 1: Use a Python template (Recommended)**

**Metoda 1: Użyj szablonu dla Pythona (Zalecane)**

Create a file named `.gitignore` in your project root with this content:

Utwórz plik o nazwie `.gitignore` w głównym katalogu projektu z następującą zawartością:

```gitignore
# Python
__pycache__/
*.py[cod]
*$py.class
*.so
.Python

# Virtual environments
.venv/
venv/
ENV/
env/

# IDEs
.idea/
.vscode/
*.swp
*.swo

# Environment variables and secrets
.env
.env.local
*.pem
credentials.json

# Testing
.pytest_cache/
.coverage
htmlcov/

# OS
.DS_Store
Thumbs.db

# Project-specific
*.log
app.log
```

**Method 2: Use GitHub's template**

**Metoda 2: Użyj szablonu GitHub**

When creating a repository on GitHub, check **"Add .gitignore"** and select **"Python"** from the dropdown.

Podczas tworzenia repozytorium na GitHubie zaznacz **"Add .gitignore"** i wybierz **"Python"** z listy rozwijanej.

**Method 3: Use `gh` CLI**

**Metoda 3: Użyj `gh` CLI**

```bash
# Generate Python .gitignore automatically
# Wygeneruj .gitignore dla Pythona automatycznie

```

**Method 4: Use gitignore.io**

**Metoda 4: Użyj gitignore.io**

Visit [gitignore.io](https://www.toptal.com/developers/gitignore) and search for "Python" to generate a comprehensive `.gitignore` file.

Odwiedź [gitignore.io](https://www.toptal.com/developers/gitignore) i wyszukaj "Python", aby wygenerować kompletny plik `.gitignore`.

---

### ⚠️ Important: Add `.gitignore` BEFORE first commit

### ⚠️ Ważne: Dodaj `.gitignore` PRZED pierwszym commitem

If you already committed files you want to ignore, you need to remove them from Git's tracking:

Jeśli już scommitowałeś pliki, które chcesz ignorować, musisz je usunąć ze śledzenia Gita:

```bash
# Remove from Git tracking but keep the file locally
# Usuń ze śledzenia Git, ale zachowaj plik lokalnie
git rm --cached -r .venv/
git commit -m "Remove .venv from tracking"
```

🔒 **Security reminder / Przypomnienie o bezpieczeństwie:**

NEVER commit files containing secrets (passwords, API keys, tokens). Always add them to `.gitignore` first!

NIGDY nie commituj plików zawierających sekrety (hasła, klucze API, tokeny). Zawsze dodaj je najpierw do `.gitignore`!

Dobry README zazwyczaj zawiera:

**Tips for a great README / Wskazówki do świetnego README:**

- **Use headers** (`#`, `##`, `###`) to organize content

  **Używaj nagłówków** (`#`, `##`, `###`) do organizacji treści

- **Add code examples** in fenced blocks (\`\`\`python ... \`\`\`)

  **Dodaj przykłady kodu** w blokach (\`\`\`python ... \`\`\`)

- **Include badges** for build status, coverage, version (optional but professional)

## 💡 5️⃣ Debugging and Logging / Debugowanie i logowanie

The simplest way to check what your code does is with `print()` or `pprint()` (pretty print for complex data).

Najprostszy sposób, by sprawdzić co robi Twój kod, to `print()` lub `pprint()` (ładniejsze formatowanie złożonych danych).

It works, but it quickly becomes messy and hard to maintain or update.

To działa, ale szybko staje się nieczytelne i trudne w zarządzaniu i aktualizacji.

In practice, it's better to use a [**debugger**](https://en.wikipedia.org/wiki/Debugger) (like in PyCharm) and the [**`logging` module**](https://docs.python.org/3/library/logging.html), which let you inspect program behavior without cluttering code with prints.

W praktyce lepiej korzystać z [**debuggera**](https://pl.wikipedia.org/wiki/Debugger) (np. w PyCharm) oraz [**modułu `logging`**](https://docs.python.org/3/library/logging.html), które pozwalają analizować działanie programu bez zaśmiecania kodu printami.

---

### 🔍 Comparison: print vs pprint vs logging vs debugger
### 🔍 Porównanie: print vs pprint vs logging vs debugger

| Narzędzie / Tool | Kiedy używać / When to use | Zalety / Pros | Wady / Cons |
|------------------|----------------------------|---------------|-------------|
| `print()` | Szybki test / Quick check | Natychmiastowy rezultat / Immediate result | Zaśmieca kod, trudny do wyłączenia / Clutters code, hard to disable |
| `pprint()` | Złożone struktury danych / Complex data | Czytelny format / Readable format | Jak print — trudny do zarządzania / Like print — hard to manage |
| `logging` | Produkcja, długoterminowe śledzenie / Production, long-term tracking | Poziomy ważności, zapis do pliku / Severity levels, file output | Wymaga konfiguracji / Requires setup |
| **Debugger** | Szczegółowa analiza / Deep analysis | Krok po kroku, brak zmian w kodzie / Step-by-step, no code changes | Wymaga nauki / Learning curve |

### 🧾 Logging

The [`logging`](https://docs.python.org/3/library/logging.html) module is used to record what the program is doing — either on screen or to a file.

Moduł [`logging`](https://docs.python.org/3/library/logging.html) służy do zapisywania informacji o tym, co robi program — na ekranie lub w pliku.

It lets you control the level of detail (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`) and easily log exceptions.

Pozwala kontrolować poziom szczegółowości komunikatów (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`) oraz łatwo rejestrować wyjątki.

You can also decide whether logs should be written to a file, displayed on the screen, or both.

Można też ustawić, czy logi mają być zapisywane do pliku, wyświetlane na ekranie, lub oba jednocześnie.

🧩 **Zadanie / Task:**

Create a file `debug_demo.py`:

Utwórz plik `debug_demo.py`:

```python
import logging
from pprint import pprint

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    handlers=[
        logging.FileHandler("app.log"),  # zapis do pliku / log to file
        logging.StreamHandler()          # pokazuj na ekranie / show on screen
    ]
)

logging.info("Program started")

x = 10
y = 0

# Proste sprawdzenie / Simple check
print(f"{x=}, {y=}")
pprint({"x": x, "y": y})
logging.info(f"{x=}, {y=}")

try:
    result = x / y
except ZeroDivisionError as e:
    logging.exception("Division by zero occurred!")
finally:
    logging.info("Program finished")
```

Run the program and check both the console output and the `app.log` file.

Uruchom program i sprawdź zarówno wynik w konsoli, jak i plik `app.log`.

**Expected output / Oczekiwany rezultat:**
```
x=10, y=0
{'x': 10, 'y': 0}
2025-01-15 10:30:45,123 [INFO] x=10, y=0
2025-01-15 10:30:45,124 [ERROR] Division by zero occurred!
Traceback (most recent call last):
  ...
ZeroDivisionError: division by zero
2025-01-15 10:30:45,125 [INFO] Program finished
```

Check that `app.log` file was created with the same log messages.

Sprawdź, że plik `app.log` został utworzony z tymi samymi wiadomościami logów.

---

🧠 **Why this matters / Dlaczego to ważne:**

`print()` and `pprint()` are fine for quick checks — fast but unstructured.

`print()` i `pprint()` są dobre do szybkich testów — szybkie, ale niekontrolowane.

`logging` lets you centrally manage messages, write them to files, and automatically capture exceptions.

`logging` pozwala centralnie zarządzać komunikatami, zapisywać je do plików i automatycznie rejestrować wyjątki.

A debugger shows the detailed execution flow and variable state without modifying code.

Debugger pokazuje szczegółowy przebieg programu i stan zmiennych bez zmiany kodu.

### 🐛 Zadanie z debugowaniem / Debugging Task

Dzięki temu Twój program działa identycznie na każdej maszynie, niezależnie od lokalnych ustawień — specyfikacja kontenera gwarantuje spójność.
